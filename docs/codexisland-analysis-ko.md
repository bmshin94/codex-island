## 1. 이게 뭐 하는 프로젝트인가

**맥북 노치를 아이폰 다이나믹 아일랜드처럼 만들어서, AI 사용량 한도를 실시간으로
보여주는 macOS 앱.** 한 줄 소개는 *"Your AI usage limits, living in your notch."*

Claude Code / Codex 같은 AI 코딩 도구는 "5시간에 이만큼"이라는 사용 한도가 있는데,
지금 얼마나 썼는지 알 방법이 없어서 작업 중에 갑자기 막힌다. 이 앱은 그 수치를
화면 맨 위 노치에 상시 띄워준다. 자동차 연료 계기판의 AI 버전.

### 동작 방식

| 상태 | 화면 |
|---|---|
| 평소 | 노치 위 검은 알약 (티 안 남) |
| 마우스 올림 (hover) | `Claude 62% · 2h12m 뒤 리셋` 미리보기 |
| 클릭 (expand) | 전체 패널 — 좌우 스와이프로 3화면 |

펼친 패널의 3개 화면:

1. **Usage** — 5시간/주간 한도 그래프 (링·막대·계단·숫자·스파크라인 5종)
2. **Cost** — 로컬 세션 로그를 읽어 계산한 오늘/이번 달 예상 비용과 토큰 수
3. **Overview** — 1년치 사용 기록을 깃허브 잔디밭 형태로 표시

노치 없는 디스플레이에서는 메뉴바 알약으로 자동 폴백하고, 아일랜드 실루엣 바깥은
마우스 이벤트를 통과시켜 밑에 있는 앱을 가리지 않는다.

### 지원 프로바이더 (4종)

| 프로바이더 | 인증 소스 |
|---|---|
| Claude (Claude Code) | 키체인 `Claude Code-credentials` / `~/.claude/.credentials.json` |
| Codex (ChatGPT CLI) | `~/.codex/auth.json` |
| Grok | `~/.grok/auth.json` (`grok login` 필요) |
| Antigravity (Google) | `agy` CLI 키체인 |

### 기타 특징

- 한도 임박 시 경고/위험 2단계로 아일랜드 색이 변하고 펄스
- 사용량 카드를 이미지로 뽑아 SNS 공유 (금액/토큰 규모에 따라 흰색 → 검정 → 파랑 등급)
- 영어 / 중국어 간체 지원 (한국어 없음)
- Sparkle 기반 자동 업데이트, 유니버설 바이너리(arm64 + x86_64), macOS 13+
- 텔레메트리·애널리틱스·크래시 리포팅 전부 없음, 전 계산 온디바이스

## 2. 설치 및 사용법

### 설치

```sh
brew install --cask ericjypark/tap/codexisland
```

한 줄로 다운로드 + 설치 + Gatekeeper 격리 속성 해제까지 끝난다.

직접 받는 경우에는 릴리즈에서 `.dmg`를 받아 `/Applications`에 넣고:

```sh
xattr -dr com.apple.quarantine /Applications/CodexIsland.app
```

> 이 명령이 필요한 이유: 애플 Developer ID($99/년)를 사지 않아 앱이 미서명이다.
> 업데이트 무결성은 Sparkle의 EdDSA 서명으로 독립 검증한다.
> `-dr`의 `r`(재귀)이 필수 — Sparkle이 중첩 헬퍼(Updater.app 등)를 포함하기 때문에
> 비재귀로 하면 "The updater failed to start"가 뜬다.

### 첫 실행

비밀번호나 API 키를 묻지 않는다. 터미널에서 `claude`를 한 번 실행해두거나
Claude 데스크톱 앱을 켜두면 끝. 인증이 없으면 `auth required — run claude`가 표시된다.

### 조작

| 동작 | 결과 |
|---|---|
| 노치에 마우스 올리기 | 사용률 미리보기 |
| 클릭 | 전체 패널 펼치기 |
| 좌우 스와이프 | Usage ↔ Cost ↔ Overview |
| **⌘ + 클릭** | 그래프 스타일 순환 |
| `synced Xs ago` 클릭 | 즉시 새로고침 |
| 톱니바퀴 또는 **⌘,** | 설정 |
| **⌘Q** (포인터가 아일랜드 위) | 종료 |

설정은 General(로그인 시 실행, 5m/15m/30m 갱신 주기, 언어, 알림 임계값),
Display(사용량/잔량 표시, 차트 스타일, 대상 디스플레이), Providers(프로바이더 선택,
토큰 카운팅 모드, 통화 — USD/KRW 등 9종) 3탭.

## 3. 코드 구조 (Swift 약 19,800줄 / 196개 파일)

```
Sources/
├── Window/       (415줄)   노치 위 테두리 없는 오버레이 창, 디스플레이 변경 감지
├── Usage/       (2,605줄)  프로바이더 API 호출 + 인증 읽기 + 폴링 스케줄
├── Cost/        (3,149줄)  로컬 세션 로그(.jsonl) 파싱 → 토큰/비용 집계
├── Views/       (6,246줄)  SwiftUI 화면 전체 (차트 5종 포함)
├── Sharing/     (1,501줄)  사용량 카드 이미지 생성 및 공유
├── Recovery/      (455줄)  유실된 Claude 사용 기록 복구
├── Model/       (1,694줄)  설정 저장소들
├── Update/         (34줄)  Sparkle 래퍼
└── Theme/         (215줄)  색/애니메이션
```

Xcode 프로젝트도 SwiftPM 패키지도 없다. `build.sh`가 `swiftc`로 소스를 직접 컴파일하고
`lipo`로 두 아키텍처를 합쳐 `.app`을 만든다.

## 4. 플러그인인가, 스킬인가, MCP인가 → 셋 다 아니다

| 종류 | 정체 | 실행 주체 |
|---|---|---|
| MCP | AI에게 도구를 제공하는 규격 | Claude가 실행 |
| 스킬 | AI에게 주는 설명서 | Claude가 읽음 |
| 플러그인 | 스킬 + MCP + 명령어 묶음 | Claude Code 내부 |
| **CodexIsland** | **독립 네이티브 macOS 앱** | **단독 실행** |

Claude와의 접점은 단 하나 — **Claude Code가 저장해둔 로그인 정보를 읽기 전용으로
참조**한다는 것뿐이다.

> 코드에 `mcpOAuth`라는 단어가 나오지만, 이는 "키체인에 MCP 서버별 토큰도 함께
> 들어있으니 그건 건너뛰고 실제 로그인 토큰을 골라야 한다"는 **회피 로직**이다.
> MCP 기능이 아니라 MCP를 피하는 코드다.

## 5. API 토큰이 필요한가 → 별도 발급 불필요

`sk-ant-...` 같은 유료 API 키를 만들 필요가 없다. 이미 로그인된 OAuth 토큰을 재사용한다.

탐색 순서:

1. `CLAUDE_CODE_OAUTH_TOKEN` 환경변수
2. macOS 키체인 `Claude Code-credentials`
3. `$CLAUDE_CONFIG_DIR/.credentials.json` (보통 `~/.claude/.credentials.json`)

그 토큰으로 호출하는 엔드포인트는 딱 두 개:

```
Claude → https://api.anthropic.com/api/oauth/usage
Codex  → https://chatgpt.com/backend-api/wham/usage
```

**"내 한도가 얼마 남았나"만 조회**하는 주소라 추론 비용이 발생하지 않는다.

### 절대 규칙: 토큰은 읽기만 한다

Anthropic은 리프레시 토큰을 호출할 때마다 회전시키고, 구 토큰이 재사용되면
**토큰 패밀리 전체를 폐기**한다. 앱이 독자적으로 갱신하면 사용자의 CLI 로그인이
통째로 무효화된다. 실제로 과거에 사고가 났고, 그래서 `CLAUDE.md`에 재도입 금지가
명시되어 있다.

### 키체인 읽기의 함정 (참고할 가치 있는 부분)

Claude Code가 약 8시간마다 `security add-generic-password -U`로 토큰을 갱신하는데,
그때 키체인 항목의 파티션 목록이 `apple-tool:`로 리셋되면서 앱별 접근 권한이
조용히 날아간다. Developer ID 서명이 있어도 살아남지 못한다. 그래서 이 앱은
**앱 내부 SecItem API가 아니라 `/usr/bin/security` 실행을 1순위**로 쓴다.

## 7. 로컬 에이전트 구축에 도움이 되나

**직접적으로는 아니다.** AI를 호출하는 코드가 한 줄도 없다. 숫자를 읽어 그리는 앱이다.

**간접적으로는 매우 유용하다.** 에이전트를 만들면 반드시 부딪히는 문제들의
검증된 해법이 들어있다.

| 가져다 쓸 것 | 위치 |
|---|---|
| macOS 키체인에서 인증 정보 안전하게 읽기 | `Sources/Usage/ClaudeCredentials.swift` |
| 로컬 세션 로그(.jsonl) → 토큰/비용 집계 | `Sources/Cost/` (3,149줄) |
| 레이트리밋 안 걸리는 폴링 설계 (최소 5분, 백오프, 429 쿨다운) | `Sources/Usage/` |
| 태그 푸시 → 빌드 → 서명 → 릴리즈 → Homebrew 전자동 | `.github/workflows/release.yml` |

정리하면 **"부품 창고"로 쓰기 좋다.**

## 9. 수익화 분석

### 핵심 통찰

> 사람들은 **"숫자를 보는 것"** 에는 돈을 내지 않는다.
> 돈은 **"그래서 무엇을 해야 하는가"** 와 **"누가 얼마 썼는지 정산"** 에 있다.

무료 17개가 전부 "보여주기"에서 멈춰 있고, 그다음 단계가 비어 있다.

```
3층  정산 / 예산 / 규정 준수   ← 회사가 지불 (비어 있음)
2층  절약 / 최적화 제안        ← 개인도 지불 (거의 비어 있음)
1층  숫자 보여주기             ← 무료 17개가 경쟁 중
```

### 아이디어 1: 팀 AI 지출 정산 SaaS (최우선)

"우리 개발팀 12명이 이번 달 AI에 얼마 썼고 어느 프로젝트에 나갔는지"를
회계팀이 볼 수 있게 만드는 제품.

개인은 `$47`이 나와도 넘어가지만, 회사는 매달 반드시 답해야 하는 질문이다
(비용 귀속, 예산 편성, ROI 보고). 감정이 아니라 프로세스라서 지불이 발생한다.

무료 툴이 따라올 수 없는 영역 — 여러 사람 데이터 통합, SSO/권한, 프로젝트별
비용 분배, 예산 초과 알림, 회계용 리포트, 퇴사자 데이터 보존. 무료 툴의 세계관은
"내 노트북 안"에서 끝나므로 애초에 경쟁 제품이 아니다.

| 항목 | 내용 |
|---|---|
| 가격 | 5인 무료 → 이후 인당 $6~10/월 |
| 타겟 | AI를 적극 도입한 10~100명 개발 조직 |
| 기술 | React + Node/PHP 서버 |
| MVP | 4~8주 |
| 목표 | 20팀 × 15명 × $8 = 월 $2,400 |

**중요한 전제:** 유료 제품은 개인 노트북의 OAuth 토큰을 읽는 방식을 쓰면 안 된다.
Anthropic Admin API / OpenAI Admin·Usage API 같은 **공식 조직 단위 API**로 가야
약관 리스크가 없고 데이터도 정확하다. 스펙이 자주 바뀌므로 착수 전 최신 공식 문서
확인이 필요하다.

### 아이디어 2: 외주사·에이전시 클라이언트 청구

"A 클라이언트 프로젝트에 AI 비용 32만원이 나갔으니 청구서에 반영하세요."

외주 개발사와 AI 에이전시는 AI 비용을 고객에게 청구해야 하는데 현재는 주먹구구다.
비용 절감 툴이 아니라 **매출 증대 툴**이라 지불 저항이 훨씬 낮다.
17개 경쟁자 중 아무도 하지 않는 영역이며, 한국의 AI 외주 시장에도 비어 있다.

| 항목 | 내용 |
|---|---|
| 가격 | 회사당 $49~199/월 |
| 타겟 | AI 외주 개발사, 프리랜서 팀 |
| MVP | 3~6주 |
| 목표 | 15개사 × $99 = 월 $1,485 |

### 아이디어 3: 최적화 코치 (단독 아님, 부가 기능으로)

숫자만 보여주는 대신 행동을 제안한다.

```
기존:  "이번 달 $127 썼습니다"
개선:  "$127 중 $89가 Opus입니다. 이 작업들은 Sonnet으로 충분했고
        월 $54를 절약할 수 있습니다. 화요일마다 한도가 소진되는데
        캐싱을 켜면 40% 줄어듭니다"
```

월 $10을 내고 월 $50을 아끼면 계산이 명확하다. 다만 좋은 제안을 하려면 분석
로직의 품질이 높아야 하고 개인 대상이라 단가가 낮다. **아이디어 1/2의 프리미엄
기능으로 얹는 것이 최선.**

### 아이디어 4: 후원 + 컨설팅 (가장 안전)

| 방법 | 현실적 수입 | 난이도 |
|---|---|---|
| GitHub Sponsors | 월 $0~200 | 낮음 |
| 원본 기여 → 포트폴리오 | 간접 | 낮음 |
| 기술 블로그/영상 | 월 $0~500 | 중간 |
| AI 비용 컨설팅 | 건당 $500~3,000 | 중간 |

컨설팅은 제품 없이도 수익이 나고, 동시에 아이디어 1/2의 고객 발굴 통로가 된다.

## 10. React나 PHP로 만들 수 있나

| 만들 것 | React | PHP | Swift |
|---|---|---|---|
| 노치 오버레이 | 불가 | 불가 | 가능 |
| 데스크톱 앱 | Electron으로 가능(무거움) | 불가 | 가능 |
| 웹 대시보드 | 가능 | 백엔드만 | 불가 |
| 팀 SaaS | 가능 | 가능 | 불가 |
| 슬랙 봇 | 가능 | 가능 | 불가 |

- **노치 오버레이는 웹 기술로 불가능하다.** 투명 창, 클릭 통과, 물리적 노치 크기
  감지는 macOS 시스템 API가 필요하다. Electron으로 흉내는 낼 수 있지만 메모리
  300MB대를 상시 점유해 항상 떠 있는 앱에는 부적합하다.
- **웹 대시보드는 React로 100% 가능하다.** 오히려 모바일 접근, 팀 공유, 풍부한
  차트 라이브러리, 크로스플랫폼 등에서 유리하다.
- **PHP는 서버 언어**라 로컬 상주 앱은 만들 수 없지만, 팀 SaaS의 백엔드로는 충분하다.

권장 구성:

```
로컬 수집 스크립트 (Node) → 서버 (PHP/Node) → React 대시보드
```
